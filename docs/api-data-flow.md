# 계산 결과와 네 종류의 조회

2026-10-25. `useBacktest`는 계산 POST와 네 GET의 수명을 관리한다.

1. `POST /api/v1/backtest`: 다섯 `include_*`를 false로 보내 계산 결과를 먼저 표시한다.
2. 성공한 포트폴리오의 주식 심볼로 `/api/v1/prices`와 `/api/v1/news`를 요청한다.
   현금만 있으면 두 요청은 생략한다.
3. 제출 기간으로 `/api/v1/exchange-rates`와 `/api/v1/benchmarks`를 요청한다.

네 조회는 동시에 시작하며 도착한 자료부터 표시한다. 뉴스는 최신 뉴스이므로 날짜를
보내지 않고 화면에도 백테스트 기간과 무관하다고 표시한다. 각 조회는 27초, 계산 POST는
기존 185초 클라이언트 제한을 사용한다. 서버는 네 조회 전체의 실행 상한을 공유한다.

## 독립 상태와 재시도

주가·환율·벤치마크·뉴스 카드는 각각 로딩·성공·빈 결과·오류 상태를 표시한다.
HTTP 오류와 섹션별 timeout/error는 해당 카드의 재시도 버튼만 활성화한다.
빈 결과도 다시 조회할 수 있다. 하나의 재시도는 다른 조회를 취소하거나 다시 실행하지
않으며 계산 POST도 반복하지 않는다. 기존에 성공한 자료는 재시도 중에도 유지한다.

응답 형식이 잘못된 경우도 그 자료의 오류로 처리한다. 네트워크 성공만으로 잘못된
응답을 결과 상태에 넣지 않는다. 기존 통합 응답용 오류 안내는 이 페이지에서는 숨겨
조회 카드와 중복 안내하지 않는다.

## 병합과 취소

React 함수형 상태 갱신으로 각 응답을 가장 최신 결과에 합친다. 고정된 계산 응답을
매번 펼쳐 쓰면 앞서 완료한 다른 자료가 사라지므로 그렇게 하지 않는다.
주가 응답은 종목 정보·주가·급등락, 환율은 환율·통계, 뉴스는 뉴스만 바꿀 수 있다.
각 응답의 수집 상태도 소유한 키만 갱신한다. 투자금·거래·자산 곡선은 덮어쓰지 않는다.

벤치마크 응답의 정상 숫자로만 비교 수익률을 계산한다. 새 벤치마크 자료가 비어 있다면
이전 비교 수익률은 제거한다. 기존 금융 계산식과 POST 본문·응답 필드는 유지한다.

계산 실행 단위와 자료별 요청을 각각 AbortController로 구분한다. 새 계산·화면 이탈·
초기화는 모든 이전 요청을 취소하고, 특정 자료의 재시도는 그 자료만 취소·교체한다.
늦게 도착한 이전 실행 응답은 새 결과를 덮어쓸 수 없다.

## 배포·검증

기존 `/api/v1/market-data` GET은 네 GET으로 교체되므로 백엔드·콘솔 릴리스를 함께
계획해야 한다. 이전 탭은 새로고침해야 한다. 프록시는 기존 `/api/v1/` 전달을 유지한다.
서버 입력·응답·실행 한도는 [백엔드 API 문서](https://github.com/kyj0503/backtest/blob/dev/docs/architecture/api-boundaries.md)에 있다.

Docker 테스트는 네 자료 중 하나가 느리거나 실패한 경우, 병렬 응답 병합, 각 카드
버튼의 단독 재호출, 오래된 응답 차단, HTTP 취소, 현금만 있는 경우를 검증한다.
배포용 FE·BE·격리 MySQL 브라우저 검사에서는 합성 시세·뉴스를 사용한다. 조회 네 개를
503으로 만든 뒤 하나씩 복구하고, 해당 GET만 증가하며 계산 POST 호출 수는 그대로인지
접근 로그로 확인한다. 운영 자격증명·운영 DB는 사용하지 않는다.

## 계산 전 사람 인증

운영 화면은 Cloudflare Turnstile 인증을 완료해야 계산 버튼이 활성화된다.
Cloudflare 기본 Managed 위젯을 실행 버튼 옆에 최대 300px로 표시한다.
로고와 인증 상태는 기본 위젯이 표시하며 별도의 완료 문구는 덧붙이지 않는다.
모바일에서는 실행 버튼 위에 배치한다.
공개 sitekey는 GitHub Actions Variable `VITE_TURNSTILE_SITE_KEY` → Docker 빌드 인자
→ Vite 번들로 전달한다. 비밀키는 프론트엔드·GitHub에 넣지 않는다.

토큰은 POST `/api/v1/backtest`의 `X-Turnstile-Token` 헤더로만 보내며 요청 JSON은
변경하지 않는다. 백엔드 Siteverify 검증을 통과해야 계산이 시작된다. 403은 재인증,
503은 검증 불가/서버 혼잡 메시지로 표시한다. 성공·실패·취소 후에는 새 위젯을
렌더링해 일회용 토큰을 다시 받는다. 입력값 검증 실패는 토큰을 소비하지 않는다.
만료·위젯 오류 시 버튼을 잠그며, 로딩 실패는 인증 재시도 버튼을 제공한다.

아래 네 조회와 각 재시도는 토큰을 보내거나 계산을 재실행하지 않는다.
sitekey가 없는 운영 빌드는 계산 버튼을 잠근다. 위젯 없는 실행은 로컬 개발에서만
허용하며, 자동 통합 검증은 Cloudflare 공식 더미 키를 사용한다.
